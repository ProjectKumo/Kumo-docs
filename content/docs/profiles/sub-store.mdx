---
title: Sub-Store Profiles
description: Profiles generated by the bundled Sub-Store backend, with refresh that rebuilds the request locally.
---

When a profile is generated by Kumo's bundled [Sub-Store](/docs/app/sub-store)
backend, it is technically a remote profile, but Kumo treats it specially so
that refresh always works against the *current* local backend URL — not the
URL captured at import time, which may include a now-stale port.

## How They Differ From Plain Remote Profiles

| Aspect       | Plain remote                                 | Sub-Store managed                                        |
| ------------ | -------------------------------------------- | -------------------------------------------------------- |
| Source URL   | Fixed at import. Refresh fetches it.         | Rebuilt at refresh time against the current backend URL. |
| Target param | Whatever the upstream server returns.        | Forced to `target=ClashMeta`.                            |
| Cache        | Honors the server's cache headers.           | Forces `noCache=true` to avoid stale frontend caching.   |
| Kind capsule | `Remote`.                                    | `Remote` plus a `Sub-Store` badge.                       |

Everything else — auto-update, subscription user info, `useProxy` — works
the same.

## Import From Sub-Store

In the **Sub-Store** destination:

1. Open **Subscriptions** or **Collections**.
2. Pick the subscription you want to feed into Kumo.
3. Press **Import into Profiles**.

Kumo records the original Sub-Store download path in profile metadata, then
generates the active download URL whenever refresh runs.

## Refresh Behavior

Each refresh:

1. Reads the current Sub-Store backend URL (host, port, optional custom
   backend).
2. Rebuilds the URL with `target=ClashMeta` and `noCache=true`.
3. Performs the same fetch flow as a remote profile, including `useProxy`.

This means changing the Sub-Store port or switching to a custom backend
keeps existing Sub-Store-managed profiles working without re-import.

## When Sub-Store Is Off

If the Sub-Store backend is not running, refresh of a Sub-Store-managed
profile fails with a clear error. Start the backend from
**Sub-Store** or `kumo substore start`, then refresh again.
