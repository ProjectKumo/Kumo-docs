---
title: Overrides
description: Layer your own values on top of a profile YAML without editing the source.
---

Overrides let you change a profile's YAML at runtime without modifying the
source. Use them when you want to:

- Add a few rules to a remote subscription you don't control.
- Replace a misbehaving DNS block.
- Append a custom proxy provider for a single profile.
- Swap a logging level globally across every profile.

<Callout type="info" title="Where Kumo wins">
  Kumo always owns `external-controller`, `secret`, `mixed-port`, `mode`,
  `allow-lan`, `log-level`, `ipv6`, `find-process-mode`, Geo data settings,
  and (when TUN is on) the top-level `tun` / `dns` blocks. Overrides cannot
  win those keys — they are reapplied as the final layer.
</Callout>

## Merge Order

When Kumo composes the runtime YAML, the order is:

1. Selected profile YAML.
2. Profile-specific overrides.
3. Global overrides.
4. Kumo-controlled runtime settings (always last).

## Merge Operators

The override layer supports Sparkle-style sequence operators and Clash Verge
Rev rule operators:

| Operator              | Effect                                            |
| --------------------- | ------------------------------------------------- |
| `+rules`              | Prepend entries to the `rules` array.             |
| `rules+`              | Append entries to the `rules` array.              |
| `prepend-rules`       | Same effect as `+rules`, alternate spelling.      |
| `append-rules`        | Same effect as `rules+`, alternate spelling.      |
| `delete-rules`        | Remove matching entries from `rules`.             |
| `<key>!`              | Replace `<key>` directly instead of merging.      |

The same operator shape works for other array keys (`+proxy-groups`,
`proxy-groups+`, etc.). Operator keys are consumed during generation and
are not written to the final runtime YAML.

## Where Overrides Live

Overrides are stored on disk under:

```text
~/Library/Application Support/Kumo/overrides/
  overrides.json
  files/
    <id>.yaml
    <id>.js
    <id>.log
```

- `overrides.json` is the index — it records which override files are
  enabled, their scope (global vs. a specific profile id), and their order.
- `files/<id>.yaml` is the override content. One file per override.
- `files/<id>.js` is a JavaScript override (planned).
- `files/<id>.log` captures the last run output of a JavaScript override.

## YAML First

YAML overrides land first because they are deterministic, easy to inspect,
and safe to ship. A JavaScript transform layer is on the roadmap, but the
sandbox strategy needs to be reviewed before it ships.

## Examples

### Add A Final DIRECT Rule

```yaml
# overrides/files/extra-rules.yaml
+rules:
  - DOMAIN-SUFFIX,internal.example.com,DIRECT
  - DOMAIN-KEYWORD,corp,DIRECT
```

This prepends two rules ahead of whatever the profile already has.

### Replace The DNS Block Entirely

```yaml
# overrides/files/replace-dns.yaml
dns!:
  enable: true
  enhanced-mode: fake-ip
  fake-ip-range: 198.18.0.1/16
  nameserver:
    - 1.1.1.1
    - 8.8.8.8
```

The `!` suffix makes this a replace rather than a merge. Note that if TUN
is on, Kumo will still write its own `dns:` block as the final layer.

### Remove A Rule

```yaml
delete-rules:
  - DOMAIN-SUFFIX,bad.example.com,REJECT
```

This removes any rule that matches that exact entry.
