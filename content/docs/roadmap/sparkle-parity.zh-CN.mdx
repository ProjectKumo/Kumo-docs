---

Kumo 将 Sparkle 作为产品能力参考进行追踪,而非作为 Electron 实现目标。
目标是在保持 Kumo 原生 macOS 的同时,在 Mihomo 控制、系统集成、诊断、更新和
备份工作流方面达到等效覆盖。

## 状态图例

- `implemented`: 通过共享的 `KumoCoreKit` 行为可用。
- `partial`: 可见或持久化表面存在,但对等不完整。
- `planned`: 尚无完整实现,但架构已为它预留位置。
- `deferred`: 有意推迟到前置条件稳定后。

## 实现顺序

1. 稳定结构化配置流水线和控制器契约测试。
2. 扩展运行时监管和事件流,同时保持本地进程模式为默认。
3. 在特权服务安装之前添加系统代理恢复和服务就绪抽象。
4. 在稳定的控制层之上构建 Sub-Store、备份、更新和高级 UI 功能。
5. 通过 CLI 快照、服务测试、迁移测试和手动 QA 检查清单提高发布质量。

## 非目标

- 不移植 Sparkle 的 Electron 渲染器或巨型 IPC 表面。
- 在沙箱化和审计行为被明确设计之前,不添加 JavaScript 覆写规则。
- 在服务模式就绪之前,不将 TUN、PAC guard 或特权网络作为主要的日常流程的一部分。
