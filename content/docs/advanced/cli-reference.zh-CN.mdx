本页是 `kumo` 二进制文件的权威参考。每条命令都接受 `--help` 获取内联参考,以及 `--json` 以从人类可读文本切换到稳定的 JSON 信封。

信封格式始终为:

```json
{ "ok": true,  "data": <payload> }
// 或
{ "ok": false, "error": { "code": "...", "message": "...", "details": {} } }
```

完整契约见 [JSON 输出](#json-输出)。

## 状态

读取当前状态。

```bash
kumo status --json
kumo st                             # 别名
```

`status` 返回核心状态、模式、控制器端点、mixed 端口、系统代理状态、运行时设置以及最后一条状态消息。

## 生命周期

控制 Mihomo 核心进程。

```bash
kumo start --core /path/to/mihomo   # 显式指定核心
kumo start                          # 自动发现核心
kumo stop
kumo restart
```

当(计划中的)Kumo Helper 安装后,`start`、`stop` 和 `restart` 会委托给它;否则回退到应用内的本地进程监管器。

## 出站模式

无需重启即可切换 Mihomo 的出站模式。

```bash
kumo mode rule
kumo mode global
kumo mode direct
```

该模式会 patch 运行中核心的 `/configs`,关闭现有连接,刷新代理组,并持久化新模式。

## 代理

```bash
kumo proxies --json                 # 所有组及其成员
kumo proxy --json                   # 别名
kumo select "Proxy" "HK-01"         # 在 select 组内选择节点
```

自动组(`URLTest`、`Fallback`、`LoadBalance`)为只读 — CLI 显示当前选中节点,但由 Mihomo 控制。

## 连接

```bash
kumo connections --json
kumo connections --close <connection-id>
kumo connections --close-all
```

每条记录携带主机、代理链、流量计数器以及来源进程元数据(Mihomo 能解析时)。

## 提供者

```bash
kumo providers --json
```

返回代理提供者和规则提供者的数量及每个提供者的元数据(名称、来源、上次刷新时间)。

## 运行时事件

```bash
kumo runtime-events --json
kumo runtime-events --limit 20
```

Kumo 运行时事件的内存环形缓冲区:核心生命周期、配置切换、系统代理变更。

## Doctor

```bash
kumo doctor --json
```

一次性报告,综合 `status`、当前配置以及发现的 Mihomo 核心列表。提交支持工单时很实用。

## 配置路径

```bash
kumo config             # `kumo config path` 的别名
kumo config path        # Application Support 目录
kumo config list        # 所有 CLI 可见路径
kumo c list             # 短别名
```

## 备份

```bash
kumo backup export ~/Documents/kumo-backup
kumo backup import ~/Documents/kumo-backup
```

备份捕获 `state.json`、profiles 目录、overrides 目录以及 Sub-Store 数据。

## 配置

```bash
kumo profile refresh "https://example.com/sub.yaml"
```

目前 CLI 暴露基于远程 URL 的刷新。第一次刷新会导入配置;后续刷新会更新现有条目。更广泛的配置管理接口(`importProfile`、`profileContent`、`updateProfile`、`deleteProfile`、按 ID 刷新、刷新所有到期配置)已通过 `KumoController` 提供给 GUI,正在加入 CLI。

## 系统代理

```bash
kumo sysproxy on --dry-run --json
kumo sysproxy on --json
kumo sysproxy off --json
```

`--dry-run` 返回 Kumo 将要运行的精确 `networksetup` 命令,但不执行它们,也不绑定 PAC 监听器。

## TUN

```bash
kumo tun enable --json
kumo tun disable --json
```

如果没有 `utun` 设备的特权所有者,`enable` 会返回清晰的服务模式错误,存储的状态会在 Mihomo 重启前回滚。

## 服务模式(计划中)

```bash
kumo service status --json
kumo service install
kumo service uninstall
```

安装和卸载使用 macOS 管理员授权。在 Helper 发布前,这些命令报告未安装状态。

## Sub-Store

```bash
kumo substore status --json
kumo substore prepare              # 将捆绑资源复制到 ~/Library/...
kumo substore start
kumo substore stop
kumo substore restart
```

后端选择见 [Sub-Store 托管](/docs/advanced/sub-store-hosting)。

## 核心

```bash
kumo core install                  # 下载托管核心
```

## Agent 技能

```bash
kumo skills status --json
kumo skills install --agent claude --scope global --dry-run --json
kumo skills install --agent all
kumo skills uninstall --agent cursor --scope project --dry-run --json
```

`--agent` 接受 `cursor`、`claude`、`codex`、`gemini`、`agents` 或 `all`。`codex` 和 `gemini` 不支持 project scope。`--agent all --scope project` 只针对支持 project scope 的 Agent。

安装默认**非破坏性**: 如果目标目录已存在且未被 Kumo 记录为已安装,命令会失败,直到传入 `--force`。

## 日志

```bash
kumo logs                                # 运行时日志(默认)
kumo logs runtime --limit 200 --level info --json
kumo logs cli --limit 5 --json
kumo logs path
kumo logs clean --dry-run --json
```


## 全局标志

| 标志                          | 说明                                                                |
| ----------------------------- | ------------------------------------------------------------------- |
| `--json`                      | 将输出切换到稳定的 JSON 信封。                                      |
| `--dry-run`                   | 预览修改系统状态的命令。                                            |
| `--loglevel <level>`          | 设置终端日志详细程度。默认 `notice`。                               |
| `--silent` / `--verbose`      | `--loglevel silent` / `--loglevel verbose` 的简写。                 |
| `-d`                          | `--loglevel info` 的简写。                                          |
| `--color <auto/always/never>` | 控制 ANSI 样式。默认自动检测 TTY。                                  |
| `--logs-dir <path>`           | 覆盖 CLI 调试日志目录。                                             |
| `--logs-max <count>`          | 限制保留的 CLI 调试日志数量。`--logs-max=0` 禁用调试日志文件。      |
| `--timing`                    | 写入进程专属的 timing JSON 文件,并在文本模式下输出摘要。            |

## JSON 输出

每条命令都接受 `--json` 并返回相同的信封格式:

```json
{
  "ok": true,
  "data": { /* 命令专属载荷 */ }
}
```

失败时:

```json
{
  "ok": false,
  "error": {
    "code": "CORE_NOT_RUNNING",
    "message": "Kumo core is not running.",
    "details": {}
  }
}
```

自动化时应根据 `error.code` 而非退出码分支:

| `error.code`                       | 触发场景                                                   |
| ---------------------------------- | ---------------------------------------------------------- |
| `CORE_NOT_RUNNING`                 | 命令需要 Mihomo 核心正在运行。                             |
| `CORE_NOT_FOUND`                   | Kumo 在任何地方都找不到 Mihomo 二进制文件。                |
| `PROFILE_NOT_FOUND`                | 请求的配置 ID 不存在。                                     |
| `PROFILE_FETCH_FAILED`             | 订阅 URL 返回错误或拒绝连接。                              |
| `PROFILE_PARSE_FAILED`             | 下载的 YAML 解析失败。                                     |
| `CONTROLLER_REQUEST_FAILED`        | Mihomo 的 external-controller 返回非 2xx 响应。            |
| `SYSTEM_PROXY_PRECHECK_FAILED`     | 目标 `host:port` 未接受本地 TCP 连接。                     |
| `TUN_REQUIRES_PRIVILEGED_OWNER`    | 在未找到特权进程时请求启用 TUN。                           |
| `CLI_LINK_NOT_INSTALLED`           | CLI 链接操作未发现可移除的内容。                           |

退出码刻意保持精简:

| 代码 | 含义                                                     |
| ---- | -------------------------------------------------------- |
| `0`  | 成功(`ok: true`)。                                       |
| `1`  | 失败(`ok: false`; `error` 解释原因)。                    |

大于 `1` 的代码保留待用。

## 日志记录

`kumo` 将每次调用的调试日志写入
`~/Library/Application Support/Kumo/logs/cli/`。终端输出由 `--loglevel` 过滤。布局见
[文件位置](/docs/advanced/file-locations)。

<Callout type="info">
Kumo 在写入日志前会对已知敏感信息(带凭证的订阅 URL、授权头)进行脱敏。在公开场所粘贴日志前仍需 sanity-check。
</Callout>
