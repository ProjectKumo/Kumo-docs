---
title: Updates
description: How Kumo checks for updates, downloads them, and installs them on macOS.
---

Kumo ships app updates through GitHub Releases. Updates are checked
asynchronously every five minutes while the app is running and you can
also kick a check off manually from **Settings → Updates**.

## Release Channels

| Channel | Manifest URL                                                                                  |
| ------- | --------------------------------------------------------------------------------------------- |
| stable  | `https://github.com/ProjectKumo/KumoApp/releases/latest/download/latest.yml`                  |
| beta    | `https://github.com/ProjectKumo/KumoApp/releases/download/pre-release/latest.yml`             |

The Settings → Updates tab can override the manifest URL for private feeds
or local testing. Leave it blank to use the default.

## Manifest Format

`latest.yml` is published alongside each release. It looks like:

```yaml
version: 0.0.1
channel: stable
downloadURL: https://github.com/ProjectKumo/KumoApp/releases/download/0.0.1/Kumo-macos-0.0.1-arm64.dmg
assetName: Kumo-macos-0.0.1-arm64.dmg
sha256: <64-character-sha256>
releaseNotes: |
  See https://github.com/ProjectKumo/KumoApp/releases/tag/0.0.1
```

The same fields are also accepted as JSON for local testing and backwards
compatibility.

## Runtime Update Flow

1. `AppUpdateManager` polls the manifest every five minutes.
2. When a new version is found, Kumo posts a **macOS notification**
   (`AppNotificationCoordinator`) with three actions:
   - **Install Now**
   - **Remind Me Later**
   - **Restart Now** (once the download is ready)
3. The download writes to `~/Library/Application Support/Kumo/updates/downloads/`.
4. The detached DMG installer writes its log to
   `~/Library/Application Support/Kumo/logs/app-update-installer.log`.
5. The installer mounts the DMG, copies `Kumo.app` over the current
   install, and re-launches the app.

`AppUpdateManager` verifies the SHA-256 in the manifest against the
downloaded artifact before invoking the installer. A checksum mismatch
aborts the update.

## When Auto-install Fails

Automatic replacement requires the current app's parent directory to be
writable. If Kumo is in a protected location (or installed for the whole
machine), the update flow reports a clear error and you can install the
DMG manually from the linked download page.

## Manual Check

Open **Settings → Updates** and click **Check for Updates**. The same
check is also exposed in the custom About window.

## Roll Back

To roll back to a specific release:

1. Download the DMG for the version you want from GitHub Releases.
2. Quit Kumo.
3. Replace `/Applications/Kumo.app` with the version from the DMG.
4. Launch Kumo.

`state.json` and `preferences.json` decode missing fields with defaults, so
downgrades do not invalidate persisted state — but features added in newer
versions will be absent.
