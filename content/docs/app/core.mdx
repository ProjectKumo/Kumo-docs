title: Core

The **Core** destination under Configure is where you choose which Mihomo
binary Kumo runs and tune the runtime settings Kumo controls on top of every
profile.

## Core Discovery

Kumo resolves the Mihomo core in this order:

1. A path passed to the CLI with `kumo start --core <path>`.
2. The `KUMO_MIHOMO_PATH` environment variable.
3. A `mihomo` binary bundled inside `Kumo.app` resources (when present).
4. Common Homebrew or system paths such as `/opt/homebrew/bin/mihomo` and
   `/usr/local/bin/mihomo`.
5. A core managed by Kumo at `~/Library/Application Support/Kumo/cores/mihomo`.

The Core page lists every candidate it finds with `KumoController.coreCandidates()`,
so you can see exactly which binary will be used.

## Managed Install

If no core is present anywhere, Kumo can install one into its own application
support directory:

- **GUI** — Click **Install Managed Core** on the Core page.
- **CLI** — Run `kumo core install` and watch the JSON envelope for progress.

Managed installs do not run with elevated privileges. They write into your
user-scoped application support directory, not into `/usr/local`.

## Runtime Settings

Kumo always appends a small set of controlled keys to whatever profile you
selected so that the running core remains controllable:

| Key                    | What Kumo controls                                            |
| ---------------------- | ------------------------------------------------------------- |
| `external-controller`  | Host and port of the controller endpoint.                     |
| `secret`               | Random secret used for controller authentication.             |
| `mixed-port`           | Mixed proxy port published to system proxy and PAC.           |
| `mode`                 | Outbound mode (Rule, Global, Direct).                         |
| `allow-lan`            | LAN access flag.                                              |
| `log-level`            | Log verbosity in the running core.                            |
| `ipv6`                 | IPv6 toggle.                                                  |
| `find-process-mode`    | Set to `always` so Connections can show app icons.            |
| Geo data settings      | Geo database URLs and update preferences.                     |
| `tun` and `dns` blocks | Replaced entirely when Kumo TUN is enabled.                   |

The values come from `CoreRuntimeSettings` and are stored in
`state.json`. The Core page exposes these as staged edits — type into the
form, then press **Apply** to commit them through `KumoController` and (when
the core is running) restart Mihomo so the generated runtime YAML matches.

## Staged Edits

System-facing forms such as Core runtime settings and System Proxy settings
stage edits in local SwiftUI state and commit them through an explicit
**Apply** action. This is intentional: it avoids writing partially typed
ports, hosts, or network service names into the shared controller layer.
