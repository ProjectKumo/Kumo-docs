The **Proxies** destination is the dedicated place for proxy groups when the
Overview pane is not enough — for example, when you want to compare delay
results across every group, or operate on a group of selectors at once.

## Groups

Proxy groups are read live from Mihomo's `/proxies` endpoint and modeled as
`ProxyGroup` values. Each group has:

- A name (e.g. `Proxy`, `Streaming`, `Auto-HK`).
- A type (`select`, `URLTest`, `Fallback`, `LoadBalance`, etc.).
- A current selection (where applicable).
- A list of member nodes.

## Selecting A Node

In any `select` group:

1. Click a node row to make it the active outbound for that group.
2. Kumo calls `PUT /proxies/<group>` to commit the choice.
3. The Overview proxy sidebar and the menu bar status item reflect the new
   selection.

For automated groups (`URLTest`, `Fallback`, `LoadBalance`), Mihomo decides
the selection at startup and during runtime. Kumo surfaces the current
winner but does not let you override it manually — that is the group's job.

## Latency Tests

Two test paths are available:

- **Per-node test** — `KumoController.testProxyDelay(proxy:testURL:)` runs
  `GET /proxies/<proxy>/delay` with the configured probe URL.
- **Per-group test** — the `speedometer` button on a group header runs
  `KumoController.testGroupDelay(group:)`, which Mihomo expands into a delay
  test for every node in the group.

Results update the delay pill on each row. Timeouts paint the pill red and
keep the previous value visible until the next successful test.

## Tips

- Use the toolbar search field to filter group names. Matching groups stay
  expanded so you can compare them side by side.
- Run a per-group test before switching nodes manually — Mihomo's URL tests
  are usually faster and more accurate than picking by name.
- For diagnostics, the same `/proxies/<proxy>/delay` endpoint is exposed in
  the CLI as `kumo proxies --json`. See the
  [CLI reference](/docs/cli/commands).
