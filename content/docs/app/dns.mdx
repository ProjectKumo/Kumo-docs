---
title: DNS
description: DNS resolver, fake-IP range, and nameserver configuration as Kumo writes it.
---

When TUN is enabled, Kumo replaces the profile's top-level `dns:` block with
the values you configure on the DNS form, so the running core uses exactly
what you see in the UI. When TUN is disabled, the profile's own `dns:` block
is preserved.

## What Kumo Writes

The DNS form drives these Mihomo keys:

| Key                  | Meaning                                                                                |
| -------------------- | -------------------------------------------------------------------------------------- |
| `dns.enable`         | Master flag for Mihomo's DNS server.                                                   |
| `dns.enhanced-mode`  | `fake-ip` or `redir-host`. Affects how connections are matched.                        |
| `dns.fake-ip-range`  | CIDR for synthetic IPs returned in `fake-ip` mode.                                     |
| `dns.nameserver`     | Upstream resolvers to use for DNS queries.                                             |
| `dns.fallback`       | Resolvers used when the primary nameserver hits a failure case (e.g. CNAME loops).     |
| `dns.fake-ip-filter` | Domains that should *not* be answered with synthetic IPs.                              |

## Modes At A Glance

- **`fake-ip`** is the recommended mode for TUN routing. Mihomo answers DNS
  with synthetic IPs from the configured range, then matches the destination
  IP against rules and proxy groups.
- **`redir-host`** keeps real IPs in the answer. Pick this when something
  else in the system needs the real DNS resolution.

## When TUN Is Off

If you turn TUN off, Kumo stops owning the `dns:` block — the profile's own
DNS settings (if any) drive Mihomo. This means the DNS form has no effect
on the running core until TUN is re-enabled.

For most users, that is the intended behavior: DNS hijack only makes sense
when traffic is being captured at the kernel level via TUN.
