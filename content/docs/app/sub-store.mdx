title: Sub-Store
description: The bundled Sub-Store backend, with native SwiftUI subscriptions and collections management.

**Sub-Store** in Kumo is a fully native SwiftUI surface that talks to a
local Sub-Store backend over HTTP. Kumo bundles the backend as a small Node
sidecar inside the app resources; the frontend is *not* bundled — management
lives entirely in SwiftUI.

## Anatomy Of The Page

When the backend is reachable, the page shows a single thin toolbar plus a
list/detail layout:

- A `Subscriptions` / `Collections` segmented picker.
- An overflow `⋯` menu with advanced screens, restart, stop, and *Open Log*.
- A backend connection settings popover.

Two main sections render their own list-detail layout:

| Section       | What lives here                                                  |
| ------------- | ---------------------------------------------------------------- |
| Subscriptions | Subscriptions you manage in Sub-Store, with edit / import flows. |
| Collections   | Subscription groups exposed as a single download URL.            |

Power-user surfaces — Files, Modules, Artifacts, Archives, Share Tokens,
Server Settings, Backend Logs — are presented on demand as sheets launched
from the overflow menu rather than living in a permanent sidebar. That keeps
the default screen focused on subscriptions.

## Backend Lifecycle

The bundled Node sidecar is started, stopped, and restarted by
`SubStoreSupervisor`. The lifecycle commands are also exposed in the CLI:

```bash
kumo substore status --json
kumo substore prepare        # copy bundled resources into application support
kumo substore start
kumo substore stop
kumo substore restart
```

Bundled resources are copied from `KumoCoreKit` resources to:

```text
~/Library/Application Support/Kumo/substore/resources/
  manifest.json
  node/bin/node
  backend/sub-store.bundle.js
```

Runtime data lives under `substore/data/` (matching `SUB_STORE_DATA_BASE_PATH`).

## Backend Settings

The connection settings popover exposes:

- A toggle to enable / disable Sub-Store.
- Optional **Custom Backend URL** for users who run Sub-Store somewhere else
  on the network.
- **Host / LAN mode** for whether the listener binds to localhost or also
  exposes a LAN address.
- **Proxy mode** for whether Sub-Store outbound requests go through Kumo.
- Cron settings for periodic refreshes.

The settings persist to `substore/status.json` (`SubStoreStatus`).

## When The Backend Is Off

If the backend has not been prepared yet, or has been stopped, Sub-Store
falls back to a `ContentUnavailableView` with the appropriate **Start** or
**Prepare** action. There is no embedded web view — Sub-Store does not show
empty management chrome.

## Logs

`logs/substore.log` captures stdout and stderr from the backend. Each launch
writes a header line (`[ISO timestamp] starting <executable> <args>`) so log
readers can split sessions easily. The overflow menu exposes a *View Logs*
action that opens the file in your text editor.
