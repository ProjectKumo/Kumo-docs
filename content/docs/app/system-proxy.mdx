---
title: System Proxy
description: macOS system proxy in manual and PAC modes, with safe enable/disable and a dry-run preview.
---

The **System Proxy** destination configures the macOS proxy settings that
`networksetup` writes. It supports both modes that ship with macOS — manual
host:port and PAC URL — without registering a NetworkExtension or a VPN
profile.

## Modes

| Mode     | What Kumo does                                                                                                          |
| -------- | ----------------------------------------------------------------------------------------------------------------------- |
| `manual` | Configures web, secure web, and SOCKS firewall proxies plus the bypass list; turns auto-proxy state off.                |
| `pac`    | Boots a local loopback PAC server, points macOS at `http://127.0.0.1:<port>/proxy.pac`, and turns manual proxies off.   |

Disabling system proxy stops the PAC server and turns both manual and PAC
states off.

## Pre-flight Check

Before enabling system proxy, Kumo verifies that the target `host:mixed-port`
is accepting local TCP connections. This prevents macOS from being pointed at
a stale or failed listener.

After running `networksetup`, Kumo reads the OS proxy state back and only
marks the feature **Enabled** when the manual or PAC settings match the
requested mode.

## Network Service

Kumo prefers the **active route interface** by resolving
`route -n get default` against `networksetup -listnetworkserviceorder`. That
means proxy settings will be applied to the network service you are actually
using (Ethernet, Wi-Fi, USB tethering, etc.), not unconditionally to `Wi-Fi`.

You can override the resolved service from the form if you need to pin proxy
changes to a specific interface.

## Dry Run

The CLI supports a dry-run preview that returns the would-be `networksetup`
commands without executing them and without binding the PAC listener:

```bash
kumo sysproxy on --dry-run --json
kumo sysproxy off --dry-run --json
```

The same dry-run path is used by unit tests and by agent workflows that want
to preview a change before committing it.

## Staged Edits

Like the Core page, System Proxy stages your edits in SwiftUI state and
commits them through an explicit **Apply** action. The Overview pane exposes
only the master `Toggle` so the daily workflow stays one click away from
turning system proxy on or off.

## Restore (Planned)

When Kumo enables system proxy, it captures the previous proxy state for the
selected service. A future service-backed pass will restore the exact
previous values when you disable system proxy. For now, the disable path
turns Kumo-managed manual and auto-proxy states off; manually configured
values remain in place.
