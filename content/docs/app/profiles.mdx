The **Profiles** destination is where you add, switch, and refresh profiles.
A profile is a Mihomo / Clash YAML document plus a small piece of Kumo
metadata describing where it came from.

## Profile Sources

Kumo models three profile sources:

| Kind     | Where the YAML comes from                                              |
| -------- | ---------------------------------------------------------------------- |
| `remote` | A subscription URL fetched over HTTPS. Refresh re-downloads the YAML.  |
| `file`   | A local YAML file. Refresh re-reads the file from disk.                |
| `inline` | A generated fallback profile. Used when no other profile is configured. |

Sub-Store-managed profiles are a special case of `remote` that records the
original Sub-Store download path. Refresh rebuilds the request against the
current local Sub-Store backend with `target=ClashMeta` and `noCache=true`.

## Default Profile

If no profile has been imported yet, Kumo returns a minimal direct profile so
the app starts safely instead of crashing on missing configuration:

```yaml
proxies: []
proxy-groups:
  - name: Proxy
    type: select
    proxies:
      - DIRECT
rules:
  - MATCH,DIRECT
```

Everything routes direct. You can add a real profile at any time.

## Add A Profile

| Source             | How to add it                                                                                |
| ------------------ | -------------------------------------------------------------------------------------------- |
| Subscription URL   | **Profiles → Add → Remote**, paste the URL. Or `kumo profile refresh <url>` from the CLI.    |
| Local YAML file    | **Profiles → Add → Local**, choose the file with the standard `fileImporter`.                |
| Sub-Store-managed  | Generated by the bundled [Sub-Store](/docs/app/sub-store) UI and imported into Profiles automatically. |
| Services menu      | macOS *Services → Import Profile to Kumo* — sends any selected URL or text into Kumo's importer. |
| Spotlight handoff  | Tapping a Kumo Spotlight result selects the matching profile.                                |

The active profile is recorded in
`~/Library/Application Support/Kumo/profiles/current.txt`. Metadata for all
profiles lives in `profiles/profiles-metadata.json`. See
[File paths](/docs/reference/file-paths) for the full layout.

## Refresh

Refresh re-fetches a profile from its source:

- The Profiles row exposes a `Refresh` action.
- The Overview Profile card shows a `Refresh` button for the active profile.
- The CLI can refresh by id or by URL: `kumo profile refresh <id-or-url>`.

Subscription user info (used, total, expiry) is read from the
`subscription-userinfo` response header when present.

## Auto Update

Profiles can carry an auto-update interval. Kumo refreshes due profiles in
the background (`refreshDueProfiles` on the controller). The Overview Profile
card shows the configured interval alongside the relative `updated` time so
you can see at a glance whether the profile is stale.

## Edit Or Delete

The detail pane lets you:

- Inspect the raw YAML.
- Edit the profile's display name, auto-update interval, and `useProxy` flag.
- Delete the profile.

Editing the YAML directly is intentionally not exposed in the v1 UI. Use a
text editor on the file under `profiles/` if you need to hand-edit a local
profile, then `kumo profile refresh` to re-read it.
