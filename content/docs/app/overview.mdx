**Overview** is the first destination in the sidebar and is selected when the
app launches. It is a two-pane layout (`HSplitView`) inspired by single-window
utility apps.

## Left Pane — Proxy Sidebar

A searchable list of proxy nodes grouped by **proxy group**. Each row shows:

- A **country flag** inferred from the node name (or asynchronously filled in
  via a GeoIP lookup if the name is ambiguous).
- A **delay pill** with color coding:
  - Green for delays under 300 ms.
  - Orange for delays at 300 ms or more.
  - Red on timeout.
  - `—` when the delay is not known.
- A `speedometer` button next to each group header that triggers an HTTP
  latency test for every node in that group.

Tapping a row selects the node and commits the choice to the running core
(through `KumoAppStore.selectProxy(group:proxy:)`).

Typing in the search field filters node names and force-expands every matching
group so hits show up in a single click.

### Country Flags

Flags resolve in three layers, in order:

1. **Name parsing** — Kumo first looks for a flag emoji already embedded in
   the node name. If none, it matches the name against localized region names
   (English plus several CJK locales) and a short list of common aliases
   (`USA`, `UK`, `香港`, `狮城`, etc.). A second pass splits the name into ASCII
   letter tokens and tries ISO 3166-1 alpha-2 codes.
2. **GeoIP fallback** — when name parsing returns nothing, Kumo resolves the
   node's server hostname via `ipwho.is` and caches the result for 30 days
   under `~/Library/Application Support/Kumo/proxy-geo-cache.json`.
3. **Globe placeholder** — shown only when both layers come up empty. Kumo
   never invents a country.

### Stopped State

When the core is not running, the sidebar does not collapse to an empty
state. Instead, it shows a read-only preview of the proxy groups parsed
offline from the selected profile's YAML. Rows are dimmed to about 55 % and
row taps, context menus, and per-group speed tests are disabled. Selection
state is intentionally hidden because the live core decides actual selection
at start time (saved selections plus `URLTest` / `Fallback` group types).

The moment the core starts running, the sidebar swaps in the live data from
`/proxies` without rearranging rows — both sources sort case-insensitively by
name.

## Right Pane — Status Cards

Four cards stacked vertically, each backed by a Liquid Glass surface
(`kumoGlassCard`). Start / Stop and the mode picker are not duplicated here
because the toolbar already owns them.

### Profile Card

- Profile name, source description (URL or file path), kind capsule
  (`Local`, `Remote`, `Inline`, plus `Sub-Store` when applicable).
- Relative-time `updated` timestamp and configured auto-update interval.
- For remote subscriptions that report `subscriptionUserInfo`, a used / total
  `ProgressView` and an optional expiry date.
- A `Refresh` button and a deep link into the Profiles destination.

### Traffic Card

- `↑ Upload` and `↓ Download` rows fed by the controller `/traffic` WebSocket.
- Reads `0 KB/s` on both rows when the core is stopped — a calm signal that
  nothing is flowing.
- Collapsible: tapping the header expands an 80 pt area chart of combined
  throughput over the last 60 seconds, sourced from a rolling 60-sample
  buffer. When the buffer is empty (the core hasn't run this session), the
  expanded area shows a *"Start Kumo to see traffic history"* placeholder.

### System Proxy Card

- A master `Toggle` that calls `setSystemProxyEnabled(...)` directly.
- Endpoint, mode (`manual` or `pac`), and network service from the current
  `SystemProxySettings`.
- A deep link to **Configure → System Proxy** for staged edits such as port,
  bypass list, or PAC script.

### TUN Card

- A master `Toggle` (`setTunEnabled(...)`).
- Stack and auto-route summary from the runtime TUN settings.
- The most recent TUN error, when present.
- A deep link to **Configure → TUN** for detailed settings.

## Why The Stopped State Is Calm

The toolbar Start / Stop button, the menu bar status item, and the four cards
already communicate the stopped state. Kumo intentionally does not render a
giant in-pane banner saying "not running". Failures *do* escalate: failed
start/stop operations post a macOS system notification through
`AppNotificationCoordinator` so you notice even when the main window is hidden
or occluded.
