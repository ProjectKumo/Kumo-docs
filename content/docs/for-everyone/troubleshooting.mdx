This page covers the things people hit most often when they first try
Kumo. If your problem is not here, try the
[FAQ](/docs/for-everyone/faq) or open an
[issue on GitHub](https://github.com/ProjectKumo/KumoApp/issues).

## "Kumo won't start" — Start does nothing

You press **Start** in the Overview, and the status flips back to
**Stopped** a moment later.

The usual suspects:

- Kumo cannot find a Mihomo binary. Open **Settings → Core**, click
  **Install managed core**, and try again.
- The mixed port (the local port Kumo proxies through) is already
  taken by another app. Quit that app, or change the port in
  **Settings → Core**.

If neither helps, the **Logs** destination in the sidebar shows what
Mihomo is saying. The first red line is usually the real reason.

## "System Proxy keeps flipping back to off"

You toggle **System Proxy** on, and it snaps back to off with an error.

The two main causes:

1. The proxy is not actually ready yet. Kumo checks that the local
   port is accepting connections before flipping system proxy on. If
   it is not, the toggle refuses. Wait a few seconds after **Start**
   and try again.
2. macOS reports a different active network than the one Kumo is
   trying to change. Open **Settings → System Proxy** in Kumo and
   pick the right service from the dropdown (usually **Wi-Fi** on a
   laptop).

## "TUN won't turn on"

Toggling **TUN** returns an error mentioning a "service mode".

That is expected for now. TUN routes your **whole Mac** through Kumo
without using system proxy, and that requires a privileged helper
that Kumo does not yet install. Until the helper ships, use
**System Proxy** instead — for most use-cases the difference is small
and System Proxy works today.

## "My subscription refuses to refresh"

Open the profile in the **Profiles** screen, hit **Refresh**, and
watch for an error toast.

- A red error with an HTTP code (403, 502, 504): the provider's server
  is rejecting your request. Check the URL has not expired, and that
  your credentials in the URL are still valid.
- A red error about parsing: the server returned something other than
  a Clash subscription. Open the URL in a browser to see what it
  actually returns; some providers return a friendly login page when
  the subscription has expired.
- A red error about timing out and your provider is only reachable
  through the proxy itself: open the profile detail pane and turn on
  **Refresh through Kumo**.

## "I see no app icons in Connections"

If the **Connections** destination shows host names but no app icons,
make sure your profile is not overriding the `find-process-mode`
setting. Kumo turns that on by default; some user-supplied profiles
disable it. The
[Power User overrides guide](/docs/power-user/overrides) shows how to
put it back.

## "My menu bar icon is gone"

If the Kumo icon is missing from your menu bar:

- Bartender, Hidden Bar, or another menu-bar manager might be hiding
  it. Look in its overflow.
- Check **Settings → General → Show menu bar icon** is on.
- If all else fails, restart Kumo.

## "Auto-update failed"

The most common reason is Kumo is not in `/Applications`. See
[Stay up to date](/docs/for-everyone/updating#when-auto-update-fails).

## Still stuck?

Open an issue at
[github.com/ProjectKumo/KumoApp/issues](https://github.com/ProjectKumo/KumoApp/issues)
and include:

- Your Kumo version (Settings → About).
- macOS version and chip (`About This Mac`).
- A short description of what you tried.
- The last ~50 lines of the **Logs** screen if Kumo is misbehaving.

<Callout type="info">
Kumo redacts known secrets in logs, but please scan the text before
pasting it publicly — your subscription URL is the most common thing
to find in there.
</Callout>
