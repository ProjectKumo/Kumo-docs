The `kumo` executable is a stable control surface for humans, shell scripts,
and coding agents. It uses the same `KumoCoreKit` facade as the SwiftUI app,
so anything the GUI can do, the CLI can express.

## Why Use The CLI

- **Automation** — agents can call commands with `--json` and rely on a
  stable envelope.
- **Headless boxes** — no `Kumo.app` window required to start, stop, or
  refresh.
- **Diagnostics** — `kumo status --json` is the fastest way to capture the
  current state for a bug report.
- **Dry-run** — preview system changes before committing them.

## Exit Codes

| Code | Meaning                                                            |
| ---- | ------------------------------------------------------------------ |
| `0`  | Success.                                                           |
| `1`  | The command failed. `error` in the JSON envelope explains why.     |

## CLI Interaction Conventions

Kumo follows the parts of npm's CLI interaction model that make a tool feel
discoverable and scriptable:

- `kumo --help` / `kumo -h` shows common tasks, all command names, and
  next-step prompts.
- `kumo -l` / `kumo --long` expands command descriptions, usage, options,
  and aliases.
- `kumo <command> -h` and `kumo help <term>` provide command-level help.
- `kumo --version` prints only the version string.
- Conservative aliases are allowed for low-risk read paths: `status` → `st`,
  `proxies` → `proxy`, `config` → `c`.
- Commands that can write system or user state support `--dry-run` where a
  meaningful preview is possible.
