---
title: Shell Completion
description: Install zsh, bash, or fish completion for the kumo CLI.
---

`kumo completion <shell>` writes a completion script to stdout. Pipe it into
the right location for your shell.

## zsh

```bash
mkdir -p ~/.zsh/completions
kumo completion zsh > ~/.zsh/completions/_kumo

# In ~/.zshrc, before `compinit`:
fpath=(~/.zsh/completions $fpath)
autoload -U compinit && compinit
```

If you use Homebrew's zsh, `~/.zsh/completions` is already on the function
path; only the `compinit` step is required.

## bash

```bash
mkdir -p ~/.bash_completion.d
kumo completion bash > ~/.bash_completion.d/kumo

# In ~/.bashrc:
[ -f ~/.bash_completion.d/kumo ] && source ~/.bash_completion.d/kumo
```

## fish

```bash
kumo completion fish > ~/.config/fish/completions/kumo.fish
```

fish picks up the file on the next shell startup. No further configuration.

## What Completion Covers

The completion script understands:

- Top-level commands and their aliases.
- Subcommands such as `mode`, `proxies`, `profile`, `sysproxy`, `tun`,
  `service`, `substore`, `skills`, and `logs`.
- The fixed value sets for enum-like arguments (`rule|global|direct`,
  `on|off`, `cursor|claude|codex|gemini|agents|all`, `global|project`,
  `silent|error|warn|notice|http|info|verbose|silly`).
- Common option flags (`--json`, `--dry-run`, `--loglevel`, `--logs-dir`,
  `--logs-max`, `--color`, `--timing`).

Dynamic completion against the running core (profile ids, proxy names) is
on the roadmap.

## Regenerating

When you update Kumo, run the appropriate command above again to refresh
the completion script.
