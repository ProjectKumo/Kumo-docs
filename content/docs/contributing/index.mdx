screen.

## Ground rules

A few things to keep in mind before you start:

- **Be kind.** Reviewers, reporters, and other contributors are real people.
- **One change per PR.** Small, focused diffs land faster.
- **Tests are part of the change.** If you fix a bug, add a test that would
  have caught it.
- **Docs are part of the change.** If your patch alters product behaviour,
  permissions, runtime configuration, or persistence, update the relevant
  document in the same PR.
- **English in user-visible copy** unless the change is specifically about
  localization.

<Callout type="info">
If you're not sure whether a change is welcome, open a discussion or a
draft PR first. We'd rather talk early than have you sink a weekend into
something we'd have to redirect.
</Callout>

## Good first changes

These are the easiest entry points:

- Fix a typo or broken link in **these docs**
  ([Kumo-docs](https://github.com/ProjectKumo/Kumo-docs)).
- Improve an error message in `KumoCoreKit` so the cause is obvious from
  the CLI output.
- Tighten or clarify a UI string in `KumoApp` (read `AGENTS.md` first —
  copy conventions matter here).
- Add a missing test for a `KumoCoreKit` model or helper.

If you find something that looks easy on the surface but turns out to be
load-bearing, that's normal. Ask in the issue or PR and someone will help
you find a safe scope.
