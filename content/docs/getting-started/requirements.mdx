---
title: Requirements
description: What you need on your Mac to run Kumo and Mihomo together.
---

Kumo targets modern macOS hardware and the Swift 6 toolchain.

## macOS

- **macOS 15 Sequoia or later.** Kumo uses Liquid Glass and other system
  affordances that ship with macOS 15+.

## Mihomo Core

Kumo drives the [Mihomo](https://github.com/MetaCubeX/mihomo) proxy core. The
core can come from any of the following sources, in order of preference:

1. A path passed to the CLI with `kumo start --core /path/to/mihomo`.
2. The `KUMO_MIHOMO_PATH` environment variable.
3. A `mihomo` binary bundled with `Kumo.app` (when present).
4. Common Homebrew paths such as `/opt/homebrew/bin/mihomo` and `/usr/local/bin/mihomo`.
5. A core managed by Kumo itself — install it from **Configure → Core**, or
   `kumo core install` from the CLI.

If none of these resolve, Kumo shows a plain-language empty state explaining
how to provide a binary path.

## For Building From Source

You only need these if you are building Kumo yourself, not for normal use:

- **Xcode 16+** with the **Swift 6.0** toolchain.
- **XcodeGen** to regenerate `Kumo.xcodeproj` from `project.yml`
  (`brew install xcodegen`).
- `make` and a POSIX shell (both ship with macOS).

## Network Permissions

Kumo does not register a NetworkExtension or VPN profile, so the "Allow VPN
Configuration" prompt is **not** expected for System Proxy or for Mihomo TUN
mode. macOS will, however, ask for administrator authorization in a few
narrowly scoped situations:

- Installing or removing the `/usr/local/bin/kumo` CLI symlink.
- Installing the Kumo Helper for service mode (planned).

See [Permissions](/docs/reference/permissions) for the full list.
