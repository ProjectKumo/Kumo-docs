---
title: Command-line Tool
description: Install or remove the /usr/local/bin/kumo symlink that lets you call kumo from any terminal.
---

The `kumo` executable ships **inside** `Kumo.app`:

```text
Kumo.app/Contents/Helpers/kumo
```

It lives under `Helpers/` rather than `MacOS/` because macOS volumes are
case-insensitive by default — putting it next to the GUI main binary would
silently overwrite `Contents/MacOS/Kumo`.

To make `kumo` callable from any terminal, Kumo manages a symlink at
`/usr/local/bin/kumo` that points at the bundled binary.

## Install From The GUI

The first-run onboarding sheet ([First run](/docs/getting-started/first-run))
walks you through this. To revisit it later:

1. Open **Settings → General → Command Line Tool**.
2. Click **Install** (or **Remove**).
3. Approve the macOS administrator authorization prompt.

Kumo runs `ln -sfn` inside an `osascript ... with administrator privileges`
shell, so you only see one authorization prompt per operation.

## Verify

After installation, the link should point at the helper inside the running
`Kumo.app`:

```bash
ls -l /usr/local/bin/kumo
# /usr/local/bin/kumo -> /Applications/Kumo.app/Contents/Helpers/kumo

kumo --version
```

You can also check the status from the CLI:

```bash
kumo status --json | jq '.data.cliLinkStatus'
```

## Remove

The same Settings panel exposes **Remove**. macOS will prompt for
administrator authorization again. The uninstaller is safe by design:

- It runs `rm -f` only when the target symlink points at the bundled CLI.
- It refuses to delete a symlink that points somewhere else, so unrelated
  `kumo` shims you installed manually are not affected.

## Manual Install

A manual `ln -s` works too, but is no longer the recommended path:

```bash
sudo ln -sfn /Applications/Kumo.app/Contents/Helpers/kumo /usr/local/bin/kumo
```

Manual links are still detected by `kumo status` and by the Settings panel,
so you can switch back to the GUI installer later without surprises.

## When To Reinstall

There is no auto-repair: the symlink keeps pointing at whatever `kumo` lived
inside the `Kumo.app` you ran the installer from. If you move Kumo to a
different location, repeat the install step so the symlink points at the
current bundle.
