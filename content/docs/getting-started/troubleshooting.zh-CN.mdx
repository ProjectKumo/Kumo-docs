这一页覆盖了大家第一次用 Kumo 时最常碰到的问题。
如果你的问题不在这,可以看
[FAQ](/docs/getting-started/faq),或者在 GitHub 上
[提一个 issue](https://github.com/ProjectKumo/KumoApp/issues)。

## "Kumo 启动不了" —— 按启动没反应

你在概览里按 **启动**,状态过一会儿又跳回**已停止**。

常见原因:

- Kumo 找不到 Mihomo 核心。打开 **设置 → 核心**,点
  **安装托管核心**,再试。
- mixed 端口(Kumo 代理用的本地端口)被别的 app 占了。退掉那个 app,
  或者在 **设置 → 核心** 里改一下端口。

如果两个都没用,侧边栏的 **日志** 里能看到 Mihomo 在说什么。
第一条红色的输出通常就是真正的原因。

## "系统代理一直自动跳回关闭"

你打开 **系统代理**,它带着一条错误信息又跳回了关闭。

两个主要原因:

1. 代理还没真正就绪。Kumo 在打开系统代理之前会先确认本地端口已经
   能接受连接。如果还没,开关会拒绝打开。按 **启动** 之后等几秒,
   再试。
2. macOS 报告的当前网络服务和 Kumo 想改的不是同一个。
   在 Kumo 里打开 **设置 → 系统代理**,从下拉菜单里选对服务
   (笔记本上通常是 **Wi-Fi**)。

## "TUN 打不开"

切换 **TUN** 时报错,提示需要 "service mode"。

这是目前的预期行为。TUN 在不依赖系统代理的情况下把你**整台 Mac**
的流量都路由进 Kumo,这需要一个特权 helper —— Kumo 暂时还不会
自动安装这个组件。在 helper 上线之前,请用 **系统代理** 代替 ——
对大多数场景来说差别不大,系统代理今天就能正常工作。

## "订阅刷新不了"

打开 **配置** 屏幕里的那份配置,点 **刷新**,留意错误提示。

- 红色提示里带着 HTTP 状态码(403、502、504):服务商的服务器拒绝
  了你的请求。检查 URL 是不是过期了,以及 URL 里带的凭据是不是
  还有效。
- 红色提示提到解析失败:服务器返回的不是一份 Clash 订阅。把 URL
  在浏览器里打开看看真正返回的是什么 —— 有的服务商在订阅过期时
  会返回一个友好的登录页。
- 红色提示是超时,且你的服务商只能通过代理本身访问:打开配置详情
  面板,把 **通过 Kumo 刷新** 打开。

## "连接里看不到 app 图标"

如果 **连接** 屏幕里只显示主机名、看不到 app 图标,确认你的配置
没有把 `find-process-mode` 关掉。Kumo 默认会开它,但有些用户提供
的配置会关。
[进阶的 overrides 指南](/docs/advanced/overrides) 里讲了
怎么把它打回去。

## "菜单栏图标不见了"

如果 Kumo 图标从你的菜单栏里消失了:

- 可能 Bartender、Hidden Bar 或别的菜单栏管理工具把它藏到了溢出区。
  到它们的溢出列表里翻一翻。
- 检查 **设置 → 通用 → 显示菜单栏图标** 是开着的。
- 实在不行,重启 Kumo。

## "自动更新失败"

最常见的原因是 Kumo 没装在 `/Applications`。详见
[保持更新](/docs/getting-started/updates#自动更新失败怎么办)。

## 还是卡住?

到
[github.com/ProjectKumo/KumoApp/issues](https://github.com/ProjectKumo/KumoApp/issues)
开一个 issue,附上:

- 你的 Kumo 版本(设置 → 关于)。
- macOS 版本和芯片(`关于本机`)。
- 你做了什么的简短描述。
- 如果 Kumo 行为异常,**日志** 屏幕的最后约 50 行内容。

<Callout type="info">
Kumo 会在日志里抹掉它知道的几种 secret,但你贴到公网之前最好再扫一眼
文本 —— 订阅 URL 是其中最常见的、容易被忘掉的东西。
</Callout>
