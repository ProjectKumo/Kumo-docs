The `kumo` command-line tool is the same `KumoCoreKit` facade the GUI
uses, exposed as a small ArgumentParser binary. Anything the GUI can
do, the CLI can do — and vice versa — so you can mix the two without
worrying about who owns what.

## Install the CLI

There are two ways to put `kumo` on your `PATH`.

### From the app (recommended)

The first-launch onboarding sheet offers to install the CLI. If you
skipped that step, you can run it again from
**Settings → General → Install Command Line Tool**.

Behind the scenes Kumo creates a symlink at:

```bash
/usr/local/bin/kumo  →  /Applications/Kumo.app/Contents/Helpers/kumo
```

This one operation requires administrator authorization (because
`/usr/local/bin` is owned by root). You will see exactly one
`osascript` prompt; after that, no further elevation is needed.

### By hand

If you prefer to do it yourself:

```bash
sudo ln -sf "/Applications/Kumo.app/Contents/Helpers/kumo" /usr/local/bin/kumo
```

To remove the CLI later:

```bash
sudo rm /usr/local/bin/kumo
```

<Callout type="info">
Kumo only deletes its own symlink — it will not touch a `kumo` you
installed via Homebrew or by hand if it does not match the path it
expects.
</Callout>

## Verify the install

```bash
kumo --version
kumo status --json
```

The first command prints the version. The second talks to the running
GUI (or starts a controller if needed) and returns the current state
as JSON.

## Where everything lives

| Path                                                            | What it is                            |
| --------------------------------------------------------------- | ------------------------------------- |
| `/usr/local/bin/kumo`                                           | The symlink you just made.            |
| `/Applications/Kumo.app/Contents/Helpers/kumo`                  | The real CLI binary inside the app.   |
| `~/Library/Application Support/Kumo/`                           | Profiles, state, logs, overrides.     |
| `~/Library/Application Support/Kumo/logs/cli/`                  | Per-invocation CLI debug logs.        |

See [File locations](/docs/power-user/file-locations) for the full map.

## Tab completion

Print and source a completion script for your shell:

```bash
kumo completion zsh   > ~/.zsh/completions/_kumo   # zsh
kumo completion bash  > ~/.bash_completion.d/kumo  # bash
kumo completion fish  > ~/.config/fish/completions/kumo.fish  # fish
```

Then make sure the directory is on your shell's completion path.

## A first tour

Try these from any directory:

```bash
kumo status --json                              # current state
kumo start                                      # start the core
kumo mode global                                # switch outbound mode
kumo proxies --json | jq '.data[0].name'        # pull the first group
kumo doctor --json                              # one-shot health report
```

Anything that changes system state accepts `--dry-run` to preview the
action without running it. Anything that produces output accepts
`--json` to switch from human text to the stable JSON envelope.
